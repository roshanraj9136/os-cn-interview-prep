## Memory hierarchy

Computer mein memory ek pyramid ki tarah hoti hai. Upar wali tez hai par choti aur mehngi; neeche wali slow hai par badi aur sasti.

```text
        Registers      <- sabse tez, sabse choti
          Cache
           RAM
        SSD / HDD       <- sabse slow, sabse badi
```

| Level | Speed | Size | Cost per GB |
|---|---|---|---|
| Registers | Sabse tez | Bytes | Sabse mehnga |
| Cache (L1/L2/L3) | Bahut tez | KB - MB | Mehnga |
| RAM (main memory) | Tez | GB | Medium |
| SSD / HDD | Slow | GB - TB | Sasta |

Idea simple hai: CPU ko jo data turant chahiye wo registers/cache mein, jo abhi chal raha hai wo RAM mein, aur baaki sab disk par.

## Logical vs physical address <Badge type="danger" text="Most Asked" />

Jab aapka program chalta hai, usme jo addresses hote hain unhe **logical address** (ya virtual address) kehte hain. Ye CPU banata hai. **Physical address** wo hota hai jo actually RAM ke ek cell ko point karta hai.

In dono ko match karne ka kaam **MMU (Memory Management Unit)** karta hai. MMU ek hardware chip hai jo har logical address ko physical address mein badalta hai, runtime par.

```text
CPU ---- logical address ----> [ MMU ] ---- physical address ----> RAM
```

Program sirf logical addresses dekhta hai. Use pata bhi nahi chalta ki RAM mein wo kahan pada hai. Isi ko **address space abstraction** kehte hain.

### Base aur limit register

Sabse simple scheme mein do registers hote hain:

- **Base register**: process RAM mein kahan se start hota hai.
- **Limit register**: process kitna bada hai.

Har access par hardware check karta hai: `logical address < limit`? Agar haan to `physical = base + logical`. Agar nahi, to error (process doosre ki memory nahi chhoo sakta). Ye protection deta hai.

### Address binding (short mein)

Logical address ko physical se kab jodte hain:

- **Compile time**: jagah pehle se pata ho (absolute code). Rarely.
- **Load time**: program load hote waqt tay hota hai (relocatable code).
- **Execution time**: run ke dauraan badal sakta hai; isi ke liye MMU chahiye. Modern OS yahi use karte hain.

::: tip Interview mein aise bolo
A logical address is generated by the CPU during program execution, while a physical address refers to an actual location in RAM. The MMU, a hardware unit, translates every logical address to a physical one at runtime. This lets each process use its own address space without knowing where it actually sits in memory.
:::

## Contiguous allocation

Idea: har process ko RAM ka ek single continuous block do.

- **Fixed (static) partitioning**: RAM ko pehle se fixed-size tukdon mein baant do. Simple, par agar process chhota ho to baaki jagah barbaad (internal fragmentation).
- **Variable (dynamic) partitioning**: process jitna mange utna hi block do. Flexibility zyada, par beech-beech mein chhote-chhote khaali holes ban jaate hain (external fragmentation).

### First fit, Best fit, Worst fit <Badge type="danger" text="Most Asked" />

Jab naya process aata hai, usse kaunse free hole mein daalein? Teen strategies:

- **First fit**: upar se neeche, jo pehla hole bada ho usme daal do. Fast.
- **Best fit**: sabse chhota hole jisme process aa jaye. Leftover sabse kam, par bahut saare micro-holes ban jaate hain.
- **Worst fit**: sabse bada hole use karo. Soch ye ki leftover itna bada rahe ki wo bhi kaam aa jaye.

**Kaise solve karein**: har process ke liye rule lagao, chosen hole se process size ghatao, leftover usi jagah chhota hole ban jaata hai.

Example. Free holes (memory order, KB): 100, 500, 200, 300, 600. Processes order mein (KB): 212, 417, 112, 426.

**First fit:**

| Process | Hole chosen | Leftover | Holes after |
|---|---|---|---|
| 212 | 500 | 288 | 100, 288, 200, 300, 600 |
| 417 | 600 | 183 | 100, 288, 200, 300, 183 |
| 112 | 288 | 176 | 100, 176, 200, 300, 183 |
| 426 | koi bhi bada nahi | - | 426 WAIT karega |

**Best fit:**

| Process | Hole chosen | Leftover | Holes after |
|---|---|---|---|
| 212 | 300 | 88 | 100, 500, 200, 88, 600 |
| 417 | 500 | 83 | 100, 83, 200, 88, 600 |
| 112 | 200 | 88 | 100, 83, 88, 88, 600 |
| 426 | 600 | 174 | 100, 83, 88, 88, 174 |

**Worst fit:**

| Process | Hole chosen | Leftover | Holes after |
|---|---|---|---|
| 212 | 600 | 388 | 100, 500, 200, 300, 388 |
| 417 | 500 | 83 | 100, 83, 200, 300, 388 |
| 112 | 388 | 276 | 100, 83, 200, 300, 276 |
| 426 | koi bhi bada nahi | - | 426 WAIT karega |

Is example mein sirf **Best fit** chaaron processes ko place kar paaya. First fit aur Worst fit mein 426 KB wait karta hai, jabki total free memory kaafi thi. Ye hi **external fragmentation** hai: jagah hai par bikhri hui hai.

::: warning Common galti
"Best fit hamesha best hota hai" galat hai. Best fit sirf is example mein sab fit kar paaya. Generally First fit fast hota hai aur practice mein kaafi acha perform karta hai. Best fit bahut chhote unusable holes bana deta hai.
:::

### Internal vs external fragmentation <Badge type="danger" text="Most Asked" />

| Point | Internal fragmentation | External fragmentation |
|---|---|---|
| Kahan | Allocated block ke andar bachi jagah | Free holes ke beech bikhri jagah |
| Kyun | Fixed-size block process se bada | Variable allocation ke baad chhote holes |
| Example | Paging ka last page | Variable partitioning, segmentation |
| Fix | Chhote block size | Compaction, ya paging use karo |

**Compaction**: saare processes ko ek taraf khiska do taaki saari free jagah ek badi block ban jaye. External fragmentation hat jaata hai, par ye slow hai aur process ka relocatable hona zaroori hai.

## Paging <Badge type="danger" text="Most Asked" />

Paging external fragmentation ko khatam karta hai. Idea: logical memory ko fixed-size tukdon mein baanto (**pages**), aur physical memory ko bhi same size tukdon mein (**frames**). Page size = frame size. Koi bhi page kisi bhi free frame mein jaa sakta hai; continuous hona zaroori nahi.

**Page table** batata hai ki kaunsa page kaunse frame mein hai.

```text
Logical address = [ page number | offset ]

   page number ---> [ Page Table ] ---> frame number
   physical address = frame number * page size + offset
```

### Address translation (verified example)

Page size = 4 KB = 4096 bytes. Logical address = 13000. Page 3 frame 5 mein hai.

**Kaise solve karein**: page number = address / page size (integer division), offset = address % page size.

| Step | Calculation | Result |
|---|---|---|
| Page number | 13000 / 4096 | 3 |
| Offset | 13000 - 3 x 4096 = 13000 - 12288 | 712 |
| Frame (given) | page 3 -> frame 5 | 5 |
| Physical address | 5 x 4096 + 712 = 20480 + 712 | 21192 |

Toh logical address 13000 ka physical address = **21192**.

### Page table size aur multi-level paging

32-bit logical address, 4 KB pages:

- Offset = 12 bits (kyunki 2^12 = 4096).
- Page number = 32 - 12 = 20 bits -> 2^20 = 1,048,576 entries.
- Agar har entry 4 bytes ki ho: ek page table = 1,048,576 x 4 = **4 MB** per process.

Har process ke liye 4 MB sirf page table mein? Ye bahut zyada hai. Isliye **multi-level paging** aata hai: page table ko bhi pages mein todo, aur ek outer page table rakho. Pura table ek saath memory mein rakhne ki zaroorat nahi padti.

### Paging mein fragmentation

Paging mein **external fragmentation bilkul nahi** hota (saare frames same size ke hain). Haan, **internal fragmentation** last page mein ho sakta hai: agar process ka size page size ka exact multiple na ho to aakhri page mein thodi jagah khaali rehti hai. Average waste = aadha page per process.

::: tip Interview mein aise bolo
Paging divides logical memory into fixed-size pages and physical memory into equal-size frames. A page table maps each page to a frame, so a process need not be stored contiguously. This removes external fragmentation; only a little internal fragmentation can remain in the last page.
:::

::: details Follow-up: Paging mein ek memory access do baar memory kyun chhoota hai?
Bina TLB ke, pehle page table padhne ke liye ek memory access, phir actual data ke liye doosra. Isliye effective access time double ho jaata. TLB isi ko fix karta hai.
:::

## TLB (Translation Lookaside Buffer)

TLB ek chhota, bahut tez cache hai jo MMU ke andar hota hai. Ye recently use ki gayi page-table entries ko yaad rakhta hai. **TLB hit** par page table chhoone ki zaroorat nahi; **TLB miss** par page table se entry laate hain.

### EAT (Effective Access Time) numericals

**Kaise solve karein**: EAT = (hit ratio x hit time) + (miss ratio x miss time). Hit = TLB + memory. Miss = TLB + page table (1 memory) + data (1 memory).

Example 1: TLB lookup 20 ns, memory access 100 ns, hit ratio 80%.

```text
EAT = 0.80 x (20 + 100) + 0.20 x (20 + 100 + 100)
    = 0.80 x 120 + 0.20 x 220
    = 96 + 44 = 140 ns
```

Example 2: same, hit ratio 98%.

```text
EAT = 0.98 x (20 + 100) + 0.02 x (20 + 100 + 100)
    = 0.98 x 120 + 0.02 x 220
    = 117.6 + 4.4 = 122 ns
```

Jitna zyada hit ratio, utna kam EAT. Isi liye TLB itna important hai.

## Multi-level, inverted aur hashed page tables (short)

- **Multi-level paging**: page table ko layers mein todo (2-level, 3-level). Sirf zaroori parts memory mein rehte hain.
- **Inverted page table**: har physical frame ke liye ek entry (process id + page number). Table chhota rehta hai, par search slow (hashing se tez karte hain).
- **Hashed page table**: page number ko hash karke entry dhoondte hain; bade address spaces ke liye.

## Segmentation

Paging memory ko fixed tukdon mein todta hai, par program toh logical parts mein hota hai: code, data, stack, heap. **Segmentation** program ko inhi logical **segments** mein baantta hai, jo alag-alag size ke hote hain.

**Segment table** mein har segment ke liye **base** (kahan se start) aur **limit** (kitna bada) hota hai.

```text
Logical address = [ segment number | offset ]

   segment number ---> [ Segment Table: base, limit ]
   if offset < limit:  physical = base + offset
   else:               error (segmentation fault)
```

Chhota example: segment 2 ka base = 4300, limit = 400. Offset 53 valid hai (53 < 400) -> physical = 4300 + 53 = 4353. Offset 500 invalid (500 > 400) -> trap.

### Paging vs Segmentation <Badge type="danger" text="Most Asked" />

| Point | Paging | Segmentation |
|---|---|---|
| Division | Fixed-size pages | Variable-size logical segments |
| Programmer ko dikhta hai? | Nahi (OS ka kaam) | Haan (code, data, stack) |
| Address | page number + offset | segment number + offset |
| Table | Page table | Segment table (base + limit) |
| Fragmentation | Internal (last page) | External |
| Logical view | Nahi rakhta | Rakhta hai |

**Segmentation with paging** (short): har segment ko phir se pages mein tod dete hain. Isse segmentation ka logical view aur paging ka no-external-fragmentation dono mil jaate hain. Intel x86 ne yahi use kiya tha.

::: tip Interview mein aise bolo
Paging splits memory into fixed-size pages and causes only internal fragmentation, while segmentation splits a program into variable-size logical units like code, data and stack, which can cause external fragmentation. Paging is invisible to the programmer; segmentation matches the program's logical structure. Modern systems often combine both.
:::

## Swapping (short)

Jab RAM kam pade, OS kisi process ko poora ya partly disk par (swap space) bhej deta hai aur baad mein wapas laata hai. Isse zyada processes ek saath "chal" sakte hain jitni RAM mein na aayein. Zyada swapping se system slow ho jaata hai (iska ek roop thrashing hai, jo Virtual Memory page par hai).

## Yaad rakhne layak points

- Logical address CPU banata hai; physical address RAM ka actual location hai; beech mein MMU translate karta hai.
- Paging mein external fragmentation nahi, sirf internal (last page). Segmentation mein external fragmentation hota hai.
- Logical 13000, page size 4 KB, page 3 -> frame 5 => physical = 21192.
- 32-bit address + 4 KB page => 2^20 entries, 4-byte entry => 4 MB page table per process, isliye multi-level paging.
- TLB EAT: hit ratio 80% => 140 ns, 98% => 122 ns (TLB 20 ns, memory 100 ns).
- First fit fast; Best fit chhote holes; Worst fit bada hole. Diye gaye example mein sirf Best fit ne sab fit kiye.
- Internal = block ke andar barbaad jagah; external = bikhre free holes. External ka fix compaction ya paging.
- Base + limit register protection dete hain: `logical < limit`, `physical = base + logical`.
